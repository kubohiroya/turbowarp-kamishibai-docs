## 0.2 このワークショップで学ぶこと

このワークショップでは、

* ポーズ認識AI（Teachable Machine）
* 紙芝居プログラミングアプリ（TurboWarp紙芝居）
* 生成AIで作った画像素材

といった技術を組み合わせて、

**「地域の伝説の中に、自分が登場人物として参加する仕組み」**

を40分で作ります。

題材は、市川市の国府台・真間地域に伝わる「真間の手児奈（ままのてこな)」の伝説です。
あなたは手児奈に求婚する人物を1人選び、その人物の「決めポーズ」を自分の体で作り、
AIにそのポーズを覚えさせて、紙芝居の台本に組み込みます。

## 0.3 このワークショップが想定する参加者

このワークショップは、**高校生**が**2人1組**で参加することを想定しています。

* AI利用経験は問いません。
* プログラミング経験（Scratchなど）は問いません。

次のことができれば、十分に参加できます。

* マウスやキーボードの操作ができる
* Webブラウザ（Edgeなど）でページを開き、タブを切り替えられる
* Windowsのフォルダとファイルの区別がつく

わからないことがあっても、スタッフがサポートしますので、安心してください。

## 0.4 題材の扱いについて

この教材は、伝説を題材にした創作物です。読み進める前に、3つだけ確認させてください。

**1つ目。手児奈の伝説は、悲しい結末を持つ物語です。**

多くの人から求婚された手児奈は、誰か1人を選べば他の人を悲しませてしまうと思い悩み、
真間の入江に身を投げたと伝えられています。この紙芝居でも、**手児奈はどの求婚者の申し出も断ります**。
これは、あなたが考えた求婚者の出来が悪いからではありません。
「誰も選べなかった」という伝説の筋書きが、そもそもそういう物語なのです。

**2つ目。手児奈は、今も祈りの対象です。**

市川市真間の手児奈霊神堂（てこなれいしんどう）は、現在も子育てや安産を願う人がお参りする場所です。
伝説を題材にして遊ぶときにも、実際にお参りしている人がいることを忘れないでください。

**3つ目。人の姿を生成AIで描くときには、気をつけることがあります。**

この教材で使う求婚者の絵は、生成AIで事前に作ったものです。
実在する人物に似せた絵を作ったり、人を傷つける描き方をしたりしないよう注意してください。

> ⭐️ このワークショップでカメラが撮影する映像は、ポーズの識別のためだけに用いられます。パソコン上にもネットワーク上にも、どこにも保存されません。

# 1. はじめに（5分）

## 1.1 真間の手児奈の伝説

いまから1300年ほど前、このあたり（下総国・真間）に、手児奈という娘がいたと伝えられています。

手児奈はたいへん美しく、心やさしい娘でした。
その評判を聞いて、近くの村からも、遠い国からも、たくさんの男たちが求婚に訪れました。
国府の役人、馬を引く若者、入江の漁師、旅の歌人——。

しかし手児奈は、誰か1人を選ぶことができませんでした。
1人を選べば、他の人を悲しませてしまう。そう思い悩んだ手児奈は、
やがて真間の入江に身を投げたと伝えられています。

この物語は、日本でもっとも古い歌集『万葉集』に歌われています。
山部赤人（やまべのあかひと）や高橋虫麻呂（たかはしのむしまろ）が、
真間の手児奈を思う歌を残しました。
国府台・真間は、その歌に出てくる場所そのものです。

> ⭐️ 『万葉集』には、求婚した男たちの名前は出てきません。「たくさんの男が求婚した」とだけ書かれています。だからこそ、**どんな人物が求婚に来たのかは、わたしたちが想像してよい部分**です。このワークショップでは、そこを作ります。

## 1.3 この40分で作るもの

いまプレイした作品には、**求婚者が1人しか登場していません**。
このワークショップでは、ここに**あなたの求婚者**を1人追加します。

作業は3つです。

1. **求婚者を選ぶ**（5分） — 用意された「求婚者カタログ」から1人選び、名乗りのセリフを決めます。
2. **ポーズを覚えさせる**（12分） — 選んだ求婚者の「決めポーズ」を自分の体で作り、Teachable MachineでAIに覚えさせます。
3. **ブロック台本に組み込む**（12分） — 紙芝居の台本に、求婚者の情報とAIモデルのURLを書き込みます。

残りの時間で動作確認をし、クラス全員の求婚者を並べてプレイします。

<div class="concept-flow">
求婚者を選ぶ → 決めポーズを決める → AIに覚えさせる → 台本に組み込む → カメラの前で演じる
</div>

> ⭐️ 絵を描く作業は、このワークショップには含まれません。求婚者の絵は、生成AIで事前に用意してあります。自分だけの求婚者の絵を作ってみたい人は、「6.4 発展課題」を見てください。

## 1.4 この作品は、どんな技術でできているの？

![【図版未作成】AI紙芝居を構成する技術の説明図（カメラ→ポーズ認識AI→台本→画面）]{alt="AI紙芝居を構成する技術の説明図"}

| 部品                        | 役割                                                     | 今日あなたが作る部分           |
| --------------------------- | -------------------------------------------------------- | ------------------------------ |
| カメラ                      | あなたの姿を撮影する                                     | —                              |
| ポーズ認識AI                | 撮影した姿が、どのポーズかを判定する                     | **あなたのポーズを学習させる** |
| 紙芝居の台本                | 場面・セリフ・絵・待つポーズの順番を決める               | **求婚者1人分を書き足す**      |
| 紙芝居アプリ（TurboWarp紙芝居） | 台本を読み込んで、絵と音と認識を組み合わせて再生する | —                              |

ポーズ認識AIは、**正解を教えられた例から規則を見つける**しくみで動いています。
「このポーズが`kime`、この姿勢が`neutral`」という例を数十枚見せると、
AIは初めて見る映像についても、どちらに近いかを判定できるようになります。

これを「機械学習」と呼びます。あなたが今日やるのは、まさにこの「例を見せる」作業です。

> ⭐️ この教材の文章づくりにも、生成AI（ChatGPT Pro GPT-5.5）を活用しています。AIは教材づくりにも役立ちます。

## 1.5 カメラを使うときの約束

### 1.5.1 カメラを使用するとき

* ブラウザが「カメラの使用を許可しますか？」と聞いてきたら、「許可」を選んでください。
* カメラの映像は、ポーズの識別のためだけに使われます。どこにも保存されません。
* **自分以外の人が映り込まないように**、カメラの向きを調整してください。
* 他の参加者を撮影したり、画面を撮影してSNSに投稿したりしないでください。

### 1.5.2 ポーズを取るとき

* 立ち上がってポーズを取るときは、周囲の安全を確認してください。
* 机・椅子・ケーブル・足元の段差に注意してください。
* 全身が映らない場合は、上半身だけでもかまいません。

### 1.5.3 カメラの使用を終了するとき

* ブラウザのタブを閉じると、カメラはオフになります。
* 作業の終わりに、Teachable Machineのタブも閉じてください。

# 2. 求婚者を決めよう（5分）

## 2.1 求婚者カタログから1人選ぶ

配布資料の「suitors」フォルダ（求婚者カタログ）を開いてください。
手児奈に求婚する人物が、8人分用意されています。

| 番号 | 求婚者        | どんな人物か                               | 衣装名（ベース）   |
| ---- | ------------- | ------------------------------------------ | ------------------ |
| 1    | 国府の若い役人 | 都から来た役人。歌を贈る                   | `Kokufu`           |
| 2    | 馬飼いの若者   | 下総の牧で馬を育てる。馬を引いて現れる     | `Umakai`           |
| 3    | 入江の漁師     | 真間の入江で漁をする。魚を担いで現れる     | `Ryoshi`           |
| 4    | 旅の歌人       | 諸国をめぐる歌人。歌を詠む                 | `Kajin`            |
| 5    | 市の商人       | 遠い国の布や玉を売る。贈り物を差し出す     | `Akindo`           |
| 6    | 宮を守る衛士   | 弓を携えた若い衛士。まっすぐに申し出る     | `Eji`              |
| 7    | 機織りの工人   | 自分で織った布を贈る                       | `Hataori`          |
| 8    | 旅の僧         | 言葉だけを贈る                             | `So`               |

それぞれの求婚者について、3枚の絵が用意されています。

* **立ち姿**（`<衣装名>Stand`） — 登場したときの姿
* **決めポーズ**（`<衣装名>Kime`） — プロポーズをする、いちばん決まった姿
* **断られた姿**（`<衣装名>Rejected`） — 断られたあとの姿

![【図版未作成】求婚者カタログの3枚組（立ち姿・決めポーズ・断られた姿）の例]{alt="求婚者カタログの3枚組の例"}

2人1組のうち、**1人が1人の求婚者を選んでください**。相方とは別の求婚者を選ぶと、
あとで見せ合うときに楽しくなります。

> ⭐️ これらの絵は、生成AI（ChatGPT Pro GPT-5.5およびM365 Copilot）で作成しています。

## 2.2 名乗りのセリフを決める

選んだ求婚者が、手児奈の前で何と名乗るかを決めてください。
20文字くらいの短いセリフにします。

記入例：

| 項目             | 記入例                                   |
| ---------------- | ---------------------------------------- |
| 求婚者の名前     | 下総の馬飼い                             |
| 名乗りのセリフ   | 牧の馬はみな、あなたに見せたい           |
| 贈り物を差し出すか | はい（馬を1頭）                        |

「贈り物を差し出すか」は、**はい／いいえ**のどちらかを選んでください。
手児奈の断り方が、この答えによって変わります。

* 贈り物を差し出した場合 → 「そのお心、頂くことはできません」
* 贈り物を差し出さない場合 → 「お言葉だけ、いただきます」

このあと、どちらの場合も、手児奈は同じ言葉で断ります。

> ⭐️ セリフを考えるときのヒント：『万葉集』の時代の言葉づかいをまねしてもよいですし、現代の言葉でもかまいません。ただし、**相手を見下したり、しつこく迫ったりするセリフは書かないでください**。

## 2.3 決めポーズを決める

選んだ求婚者の「決めポーズ」の絵（`<衣装名>Kime`）を、画面に大きく表示してください。

この絵と**同じポーズを、自分の体で作ります**。これが、あなたがカメラの前で取るポーズになります。

* 絵のとおりにできなくてもかまいません。**自分がはっきり再現できる形**にしてください。
* 腕を大きく動かすポーズのほうが、AIは見分けやすくなります。
* 「ふつうに立っている姿」とはっきり違う形にしてください。

2人1組で、お互いにポーズを見てもらい、**毎回同じ形が作れるか**を確認してください。

# 3. ポーズを認識するしくみを作ろう（12分）

ここからは、あなたの「決めポーズ」をAIに覚えさせます。

2人1組で、次の役割に分かれて作業してください。途中で交代します。

* **モデル役**：カメラの前でポーズを取る人
* **オペレーター役**：パソコンを操作し、撮影ボタンを押す人

## 3.1 Teachable Machineのポーズプロジェクトを開く

Webブラウザで、次のURLを開いてください。

https://teachablemachine.withgoogle.com/train/pose

![【図版未作成】Teachable Machineのポーズプロジェクトの初期画面]{alt="Teachable Machineのポーズプロジェクトの初期画面"}

「Teachable Machine」は、Googleが提供する機械学習の学習ツールです。
プログラムを書かずに、画像・音・ポーズを学習させることができます。

> ⭐️ サインインは不要です。この画面のまま作業を進めてください。

## 3.2 2つのクラスを用意する

画面には「Class 1」「Class 2」という2つの箱があります。
この箱を「クラス」と呼びます。AIは、「どのクラスに近いか」を判定します。

クラスの名前を、次のように変更してください。
**名前は半角小文字で、このとおりに入力してください。** あとで台本に書くときに、この名前を使います。

| もとの名前 | 変更後の名前 | 何を覚えさせるか                   |
| ---------- | ------------ | ---------------------------------- |
| Class 1    | `kime`       | あなたが決めた「決めポーズ」       |
| Class 2    | `neutral`    | ふつうに立っている姿（決めポーズ以外） |

クラス名の右の鉛筆アイコンをクリックすると、名前を変更できます。

![【図版未作成】クラス名をkimeとneutralに変更した画面]{alt="クラス名をkimeとneutralに変更した画面"}

> ⭐️ クラスは2つだけにしてください。3つ目の「Add a class」は押さないでください。40分で終わらせるために、2クラスに絞っています。

## 3.3 ポーズを撮影する

### 3.3.1 撮影の準備

1. オペレーター役が、`kime`クラスの「Webcam」ボタンを押します。
2. カメラの使用を許可します。
3. モデル役が、カメラの前に立ちます。
4. カメラの映像に、モデル役の**全身**が映るように、ディスプレイの向きとカメラの角度を調整します。
   全身が入らない場合は、**上半身だけ**でもかまいません。
5. カメラに**他の人が映り込んでいないこと**を確認します。

![【図版未作成】カメラの前に立ち、全身が映っている状態]{alt="カメラの前に立ち、全身が映っている状態"}

### 3.3.2 決めポーズを撮影する

1. モデル役が「決めポーズ」を取ります。
2. オペレーター役が「Hold to Record（長押しして録画）」ボタンを**押したままにします**。
3. **5秒ほど**押し続けます。その間、モデル役はポーズを少しだけ動かします
   （体の向きを少し変える、腕の高さを少し変える、など）。
4. ボタンを離します。サンプル画像が50枚ほど集まります。

> ⭐️ まったく同じ姿勢だけを撮ると、少しずれたときに認識できなくなります。**少しだけ動かしながら撮る**のがコツです。

### 3.3.3 ふつうに立っている姿を撮影する

1. 役割を**交代せずに**、同じモデル役のまま続けます。
2. `neutral`クラスの「Webcam」ボタンを押します。
3. モデル役が、**ふつうに立ちます**。
4. 「Hold to Record」を5秒ほど押し続けます。その間、モデル役は
   「手を下ろす」「腕を組む」「少し歩く」「座る」など、**決めポーズ以外の動き**をします。
5. ボタンを離します。

![【図版未作成】kimeとneutralの両方にサンプル画像が集まった画面]{alt="2つのクラスにサンプル画像が集まった画面"}

> ⭐️ `neutral`は「決めポーズではない姿」の見本です。ここをいろいろな姿勢で埋めておくと、決めポーズを取ったときだけ反応するAIになります。

## 3.4 モデルをトレーニングする

画面中央の「Train Model（モデルをトレーニング）」ボタンを押してください。

![【図版未作成】Train Modelボタンと進行状況の表示]{alt="Train Modelボタンと進行状況の表示"}

トレーニングには、30秒から1分ほどかかります。

> ⭐️ トレーニング中は、**このタブを他のタブに切り替えないでください**。処理が止まることがあります。

## 3.5 モデルを確認する

トレーニングが終わると、画面右側の「Preview」にカメラの映像が表示され、
下に`kime`と`neutral`のバーが出ます。

モデル役が決めポーズを取ってみてください。

* 決めポーズを取ったとき → `kime`のバーが100%近くになる
* ふつうに立っているとき → `neutral`のバーが100%近くになる

この2つができていれば成功です。

![【図版未作成】Previewで決めポーズを取りkimeが100%になった状態]{alt="Previewで決めポーズを取りkimeが100%になった状態"}

**うまく判定されないとき**

| 症状                                     | 対処                                                           |
| ---------------------------------------- | -------------------------------------------------------------- |
| どちらのポーズでも`kime`が高い           | `neutral`のサンプルを追加で撮る（別の立ち方・座る姿も入れる）  |
| 決めポーズでも`kime`が上がらない         | `kime`のサンプルを追加で撮る。カメラに全身（上半身）が入っているか確認する |
| バーが小刻みに揺れる                     | 決めポーズをもっと大きな形に変える                             |

サンプルを追加したら、もう一度「Train Model」を押してください。

## 3.6 モデルをクラウドにエクスポートする

AIができました。これを紙芝居アプリから使えるように、インターネット上に置きます。

1. 画面右上の「Export Model（モデルをエクスポート）」ボタンを押します。
2. 開いた画面の上部で、「**Tensorflow.js**」のタブが選ばれていることを確認します。
3. 「**Upload my model**」ボタンを押します。
4. アップロードが終わるまで、30秒ほど待ちます。
5. 「Your sharable link:（共有可能なリンク）」の下に、次のような形のURLが表示されます。

```text
https://teachablemachine.withgoogle.com/models/XXXXXXXXX/
```

![【図版未作成】Export Modelの画面とsharable linkの表示]{alt="Export Modelの画面とsharable linkの表示"}

このURLを、**ワークシートに書き写してください**。次の章で使います。

URL横の「Copy」ボタンを押すと、クリップボードにコピーできます。
コピーしたら、**このタブを閉じないでください**。あとでもう一度コピーする必要が出ることがあります。

> ⭐️ このURLは、インターネット上の誰でも開ける場所に置かれます。URLそのものに、あなたの名前や撮影した映像は含まれません。学習結果（AIの中身）だけが置かれます。

> ⭐️ URLの末尾の`/`（スラッシュ）まで含めて写してください。これがないと、紙芝居アプリがモデルを読み込めません。

# 4. ブロック台本に組み込もう（12分）

ここからは、紙芝居の台本に、あなたの求婚者を書き足します。

## 4.1 ベース作品をエディタで開く

配布資料の「tekona.sb3」をダブルクリック、または次のURLからベース作品を開いてください。

【URL未定：Samplesの手児奈ベース作品のTurboWarp-Plus-Editor編集リンク】

![【図版未作成】TurboWarp-Plus-Editorで手児奈ベース作品を開いた画面]{alt="TurboWarp-Plus-Editorで手児奈ベース作品を開いた画面"}

「TurboWarp-Plus-Editor」は、Scratchによく似た画面でAI紙芝居の台本を編集できるツールです。
台本は、**ブロックを組み合わせた形**で書かれています。これを「ブロック台本」と呼びます。

> ⭐️ 画面に並んでいるブロックは、Scratchの「動かす」「言う」とは別物です。AI紙芝居専用のブロックです。

## 4.2 どこがメイン部分か

ベース作品の台本は、次の3つに分かれています。

| 部分         | 中身                                                   | 今日あなたが触るか |
| ------------ | ------------------------------------------------------ | ------------------ |
| 導入         | 真間の情景、手児奈の紹介                               | 触りません         |
| **メイン部分** | **求婚者が登場して、プロポーズし、断られる**         | **ここを作ります** |
| 結び         | 手児奈が思い悩む場面、万葉集の歌、おわり               | 触りません         |

メイン部分には、見本として**求婚者が1人だけ**入っています。
あなたは、ここに**自分の求婚者を1人追加**します。

<div class="concept-flow">
asset（モデルを登録）→ 一覧に行を追加（求婚者の情報）→ scene（使うモデルを指定）→ 保存
</div>

このあとの作業は3つです。順番どおりに進めてください。

## 4.3 ポーズモデルをassetに登録する

まず、3.6で作ったモデルのURLを台本に登録します。

台本の設定部分（`kamishibaiConfig`のかたまり）の中から、
`asset [NAME] = JSON [VALUE]`というブロックを探してください。

`NAME`の欄に、次の文字列を入力します。**自分の名前や出席番号を入れて、他の人と重ならないようにしてください。**

```text
myPoseModel
```

同じブロックの`VALUE`の欄に、次のJSONを入力します。
`https://teachablemachine.withgoogle.com/models/XXXXXXXXX/`の部分を、
**3.6で控えた自分のURLに置き換えてください。**

```json
{
  "kind": "recognitionModel",
  "delivery": "remote",
  "source": {"url": "https://teachablemachine.withgoogle.com/models/XXXXXXXXX/"},
  "loading": "lazy"
}
```

![【図版未作成】assetブロックにモデルのJSONを入力した画面]{alt="assetブロックにモデルのJSONを入力した画面"}

入力するときの注意点です。

* `VALUE`に`"myPoseModel": {...}`とは書きません。名前は`NAME`の欄に入力済みです。
* 引用符は**半角の`"`**を使います。全角の「”」は使えません。
* URLの`:`（コロン）をエスケープする必要はありません。
* `delivery`は外側、`url`は`source`の内側に置きます。

> ⭐️ `loading: lazy`は、「このモデルを使う場面の直前に読み込む」という指定です。全員分のモデルを最初にまとめて読み込むと時間がかかるため、`lazy`にしています。

## 4.4 求婚者の一覧に自分の行を追加する

次に、求婚者の情報を書き足します。

メイン部分には、求婚者の一覧を扱う`forEach`のブロックがあります。
`forEach`は、**一覧の各行について、同じ展開を繰り返す**しくみです。

* 登場する → 名乗る → プロポーズのポーズを待つ → 手児奈が断る → 断られた姿になる

という流れは、求婚者が何人いても同じです。だから、この流れは1回だけ書かれています。
**人物ごとに変わる部分だけを、一覧の表に書く**しくみになっています。

待つポーズのクラス名（`kime`）は、全員同じなので表には入っていません。
表に入るのは、名前・3枚の衣装名・セリフ・贈り物の有無だけです。

`forEach`ブロックの一覧の欄（`items`）にある、書類のアイコンをクリックしてください。
表の形で編集できる画面（一覧フォーム）が開きます。

![【図版未作成】forEachの一覧フォーム（求婚者の表）]{alt="forEachの一覧フォーム（求婚者の表）"}

表の列は、次のようになっています。

| 列名       | 型      | 入力する内容                      | 記入例                           |
| ---------- | ------- | --------------------------------- | -------------------------------- |
| `name`     | string  | 求婚者の名前                      | `下総の馬飼い`                   |
| `stand`    | string  | 立ち姿の衣装名                    | `UmakaiStand`                    |
| `kime`     | string  | 決めポーズの衣装名                | `UmakaiKime`                     |
| `rejected` | string  | 断られた姿の衣装名                | `UmakaiRejected`                 |
| `words`    | string  | 名乗りのセリフ                    | `牧の馬はみな、あなたに見せたい` |
| `gift`     | boolean | 贈り物を差し出すか（true／false） | `true`                           |

表の下の「行を追加」を押し、**2.2のワークシートに書いた内容を入力してください。**

* `stand`・`kime`・`rejected`には、**2.1の表にある衣装名**を入れます。
  `Umakai`を選んだなら、`UmakaiStand`・`UmakaiKime`・`UmakaiRejected`の3つです。
* `gift`は、`true`（贈り物を差し出す）か`false`（差し出さない）を選びます。
* 表に入れられるのは、文字・数値・true／falseだけです。画像そのものは入れられません。

入力が終わったら、一覧フォームの「保存」を押してください。
「キャンセル」を押すと、入力した内容は捨てられます。

> ⭐️ 見本の1行は消さないでください。見本と自分の行の2行になれば正しい状態です。

## 4.5 シーンに使うモデルを指定する

最後に、「この場面では、あなたのモデルを使う」という指定をします。

メイン部分の`scene`ブロックの`PROPERTIES`の欄に、次のJSONを入力します。
`myPoseModel`の部分は、4.3で自分が付けた名前にします。

```json
{"recognitionModel": "myPoseModel"}
```

![【図版未作成】sceneのPROPERTIESにrecognitionModelを入力した画面]{alt="sceneのPROPERTIESにrecognitionModelを入力した画面"}

ここに入れるのは、**URLではなく、4.3で付けた名前**です。

> ⭐️ モデルの指定は、場面ごとに必要です。前の場面の指定は、次の場面に引き継がれません。場面を分けた場合は、それぞれの`scene`に同じ指定を入れてください。

## 4.6 保存してエラーを確認する

3つの作業が終わりました。保存します。

1. 入力したフォームの「保存」を押します。
2. エディタのメニューから、SB3ファイルも保存します。

エラーが表示された場合は、次の表で原因を探してください。

| 表示・症状                                       | 確認する場所                                                                   |
| ------------------------------------------------ | ------------------------------------------------------------------------------ |
| `/assets/...`のSchemaエラー、`must be string`    | 4.3の`VALUE`。名前で包んでいないか、`url`が`source`の内側か、`delivery`があるか |
| `Unknown reference`、`Unknown actor`             | 衣装名のつづり。2.1の表と一字一句合っているか                                  |
| `recognitionModel`の指定が必要                   | 4.5の`PROPERTIES`。場面ごとに指定したか                                        |
| 読み込みは終わるが次へ進まない                   | クラス名。`kime`と`neutral`になっているか（3.2）                               |

エラーの表示には、問題のあるブロックの名前が日本語で出ます。
クリックすると、その場所に移動できます。わからないときはスタッフを呼んでください。

> ⭐️ 台本は、絵とセリフを並べただけのものではなく、**プログラム**です。名前が1文字違うだけで動かなくなるのは、プログラムだからです。逆に言えば、名前をそろえれば必ず動きます。

# 6. まとめ（3分）

## 6.1 みんなの求婚者を並べてプレイしよう

スタッフが、クラス全員の求婚者を1つの一覧にまとめます。
求婚者が次々に現れて、手児奈に断られていく紙芝居になります。

手児奈は、**全員を断ります**。誰か1人を選ぶことができないまま、物語は結びに向かいます。

## 6.2 今日あなたが達成したこと

40分で、次のことを行いました。

* 地域に伝わる伝説を読み、そこに登場する人物を自分で考えた
* 自分の体の動きを、AIに学習させた（機械学習）
* 学習したAIをインターネット上に公開し、そのURLで別のアプリから呼び出した
* プログラム（台本）の決まった場所に、決まった形でデータを書き込み、動作させた
* エラーの表示を読み、原因を探して直した

これは、**AIを「使う」だけでなく、AIを「組み込む」**作業です。

## 6.3 考えてみよう

持ち帰ってほしい問いが3つあります。答えは1つではありません。

**1. 手児奈はなぜ、誰も選べなかったのでしょうか。**

伝説では「1人を選べば他の人を悲しませてしまうから」と語られます。
では、求婚した人たちは、手児奈の何を見ていたのでしょうか。
手児奈自身が望んだことは、物語の中で語られているでしょうか。

**2. AIが「断る」とは、どういうことでしょうか。**

今日作った紙芝居では、AIがポーズを認識し、台本に書かれた断りのセリフが表示されました。
手児奈が「考えて断った」のではなく、**台本にそう書いてあったから断った**のです。
では、人の申し出に答えるAIが実際にあるとしたら、その答えは誰が決めているのでしょうか。

**3. 生成AIで人物の絵を作るとき、何に気をつけるべきでしょうか。**

今日使った求婚者の絵は、生成AIで作ったものです。
『万葉集』には求婚者の名前も姿も書かれていません。わたしたちが想像で埋めました。
その想像は、誰かを傷つけていないでしょうか。

## 6.4 発展課題

時間があるときに、次のことを試せます。

* **自分だけの求婚者の絵を作る** — 棒人間でポーズの下書きを描き、生成AI（M365 Copilotなど）に
  立ち絵をそのポーズに変えてもらいます。手順は、2026年8月1日版の教材
  「2. AIに乙姫様を描いてもらおう」と同じです。
* **断り方を増やす** — 一覧に列を追加し、`if`のブロックで手児奈の返事を枝分かれさせます。
* **求婚者を増やす** — 一覧に行を追加すれば、同じ展開がその人数分繰り返されます。
* **現代版を作る** — 舞台を現代の市川に移し、現代の人物として求婚者を考えます。

ブロック台本の書き方は、[DSL 4.0 台本作成ガイド](../../block-author-guides/dsl-4.0-block-author-guide.md)に
詳しく書かれています。
