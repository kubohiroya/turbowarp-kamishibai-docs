## 0.2 このワークショップで学ぶこと

このワークショップでは、

* ポーズ認識AI（Teachable Machine）
* 紙芝居プログラミングアプリ（TurboWarp紙芝居）
* 生成AIで作った画像素材

といった技術を組み合わせて、

**「地域の伝説の中に、自分が登場人物として参加する仕組み」**

を40分で作ります。

題材は、市川市の国府台・真間地域に伝わる「真間の手児奈（ままのてこな)」の伝説です。
あなたは手児奈に求婚する人物を1人考え、その人物が取る3つのポーズを自分の体で作り、
AIにそのポーズを覚えさせて、紙芝居の台本に組み込みます。

## 0.3 このワークショップが想定する参加者

このワークショップは、**高校生**が**2人1組**で参加することを想定しています。

* AI利用経験は問いません。
* プログラミング経験（Scratchなど）は問いません。

次のことができれば、十分に参加できます。

* マウスやキーボードの操作ができる
* Webブラウザ（Edgeなど）でページを開き、タブを切り替えられる
* Windowsのフォルダとファイルの区別がつく

わからないことがあっても、スタッフがサポートしますので、安心してください。

## 0.4 題材の扱いについて

この教材は、伝説を題材にした創作物です。読み進める前に、3つだけ確認させてください。

**1つ目。手児奈の伝説は、悲しい結末を持つ物語です。**

多くの人から求婚された手児奈は、誰か1人を選べば他の人を悲しませてしまうと思い悩み、
真間の入江に身を投げたと伝えられています。この紙芝居でも、**手児奈はどの求婚者の申し出も断ります**。
これは、あなたが考えた求婚者の出来が悪いからではありません。
「誰も選べなかった」という伝説の筋書きが、そもそもそういう物語なのです。

**2つ目。手児奈は、今も祈りの対象です。**

市川市真間の手児奈霊神堂（てこなれいしんどう）は、現在も子育てや安産を願う人がお参りする場所です。
伝説を題材にして遊ぶときにも、実際にお参りしている人がいることを忘れないでください。

**3つ目。人の姿を生成AIで描くときには、気をつけることがあります。**

この教材に入っている求婚者の絵は、生成AIで事前に作ったものです。
自分の求婚者を考えるときにも、実在する人物に似せた姿を作ったり、
人を傷つける描き方をしたりしないよう注意してください。

> ⭐️ このワークショップでカメラが撮影する映像は、ポーズの識別のためだけに用いられます。パソコン上にもネットワーク上にも、どこにも保存されません。

# 1. はじめに（5分）

## 1.1 真間の手児奈の伝説

いまから1300年ほど前、このあたり（下総国・真間）に、手児奈という娘がいたと伝えられています。

手児奈はたいへん美しく、心やさしい娘でした。
その評判を聞いて、近くの村からも、遠い国からも、たくさんの男たちが求婚に訪れました。
国府の役人、馬を引く若者、入江の漁師、旅の歌人——。

しかし手児奈は、誰か1人を選ぶことができませんでした。
1人を選べば、他の人を悲しませてしまう。そう思い悩んだ手児奈は、
やがて真間の入江に身を投げたと伝えられています。

この物語は、日本でもっとも古い歌集『万葉集』に歌われています。
山部赤人（やまべのあかひと）や高橋虫麻呂（たかはしのむしまろ）が、
真間の手児奈を思う歌を残しました。
国府台・真間は、その歌に出てくる場所そのものです。

> ⭐️ 『万葉集』には、求婚した男たちの名前は出てきません。「たくさんの男が求婚した」とだけ書かれています。だからこそ、**どんな人物が求婚に来たのかは、わたしたちが想像してよい部分**です。このワークショップでは、そこを作ります。

## 1.3 この40分で作るもの

いまプレイした作品には、**あらかじめ用意された求婚者**だけが登場しています。
このワークショップでは、ここに**あなたが考えた求婚者**を1人追加します。

作業は3つです。

1. **求婚者を考える**（5分） — どんな人物かを決め、その人物が取る3つのポーズを決めます。
2. **ポーズを覚えさせる**（12分） — 3つのポーズを自分の体で作り、Teachable MachineでAIに覚えさせて、インターネット上に置きます。
3. **ブロック台本に組み込む**（12分） — 台本の中のあなたの席の枠に、モデルのURLと言葉を書き込みます。

残りの時間で動作確認をし、クラス全員の求婚者を並べてプレイします。

<div class="concept-flow">
求婚者を考える → 3つのポーズを決める → AIに覚えさせる → 台本に組み込む → カメラの前で演じる
</div>

> ⭐️ **AIのモデルは、全員が自分の分を新しく作ります。** できあがったモデルはインターネット上に置かれ、台本にはそのURLを書き込みます。あなたの体の動きで物語が進むのは、このためです。

> ⭐️ 絵を描く作業は、このワークショップには含まれません。時間内は仮の絵のまま進めます。自分だけの求婚者の絵を作ってみたい人は、「6.4 発展課題」を見てください。

## 1.4 この作品は、どんな技術でできているの？

![【図版未作成】AI紙芝居を構成する技術の説明図（カメラ→ポーズ認識AI→台本→画面）]{alt="AI紙芝居を構成する技術の説明図"}

| 部品                        | 役割                                                     | 今日あなたが作る部分           |
| --------------------------- | -------------------------------------------------------- | ------------------------------ |
| カメラ                      | あなたの姿を撮影する                                     | —                              |
| ポーズ認識AI                | 撮影した姿が、どのポーズかを判定する                     | **あなたのポーズを学習させる** |
| 紙芝居の台本                | 場面・セリフ・絵・待つポーズの順番を決める               | **自分の席の枠を書き換える**   |
| 紙芝居アプリ（TurboWarp紙芝居） | 台本を読み込んで、絵と音と認識を組み合わせて再生する | —                              |

ポーズ認識AIは、**正解を教えられた例から規則を見つける**しくみで動いています。
「この姿が`stand`、このポーズが`kime`、この姿が`rejected`」という例を数十枚ずつ見せると、
AIは初めて見る映像についても、どれに近いかを判定できるようになります。

これを「機械学習」と呼びます。あなたが今日やるのは、まさにこの「例を見せる」作業です。

> ⭐️ この教材の文章づくりにも、生成AI（ChatGPT Pro GPT-5.5）を活用しています。AIは教材づくりにも役立ちます。

## 1.5 カメラを使うときの約束

### 1.5.1 カメラを使用するとき

* ブラウザが「カメラの使用を許可しますか？」と聞いてきたら、「許可」を選んでください。
* カメラの映像は、ポーズの識別のためだけに使われます。どこにも保存されません。
* **自分以外の人が映り込まないように**、カメラの向きを調整してください。
* 他の参加者を撮影したり、画面を撮影してSNSに投稿したりしないでください。

### 1.5.2 ポーズを取るとき

* 立ち上がってポーズを取るときは、周囲の安全を確認してください。
* 机・椅子・ケーブル・足元の段差に注意してください。
* 全身が映らない場合は、上半身だけでもかまいません。

### 1.5.3 カメラの使用を終了するとき

* ブラウザのタブを閉じると、カメラはオフになります。
* 作業の終わりに、Teachable Machineのタブも閉じてください。

# 2. 求婚者を考えよう（5分）

## 2.1 自分の求婚者を決める

あなたは、手児奈に求婚する人物を1人考えます。用意済みの8人とは別の、**あなただけの求婚者**です。

ワークシートに、次の4つを書いてください。

| 項目 | 書くこと | 記入例 |
| --- | --- | --- |
| 身分・職業 | どんな仕事をしている人か | 塩を焼く人 |
| 外見 | 服装・髪型・持ち物 | 麻の衣、頭に手ぬぐい、塩の入った壺 |
| 名乗りのセリフ | 手児奈の前で言うこと（20文字くらい） | 海の塩で、一生あなたの食事を調えます |
| 決めポーズ | プロポーズのときの姿 | 壺を両手でささげ持つ |

考えるときの手がかりは、1.1で読んだ時代です。いまから1300年ほど前、下総国の真間。国府があり、入江で漁をし、機を織り、馬を飼い、都との間を人が行き来していた土地です。

> ⭐️ 相手を見下したり、しつこく迫ったりするセリフは書かないでください。手児奈は、相手の身分や財産ではなく、自分の気持ちで断ります。

## 2.2 3つのポーズを決める

AIに覚えさせるポーズは**3つ**です。紙芝居の中で、あなたの求婚者が取る3つの姿に対応します。

| 名前 | いつの姿か | ポーズの例 |
| --- | --- | --- |
| `stand` | 登場したとき | 気をつけの姿勢。自然に立つ |
| `kime` | プロポーズをするとき | 2.1で決めた決めポーズ |
| `rejected` | 断られたとき | 肩を落として両手を下に垂らし、うつむく |

**名前は半角小文字で、このとおりです。** あとで台本に書くときに、この名前を使います。

ポーズを決めるときの約束が3つあります。

* **上半身だけで区別できる形**にしてください。足だけが違うポーズや、しゃがむポーズは見分けられません。カメラに下半身が映らない席もあります。
* **数秒そのまま止まれる形**にしてください。認識には時間がかかります。
* 3つが**はっきり違う形**になるようにしてください。

2人1組で、お互いにポーズを見てもらい、毎回同じ形が作れるか確認してください。

![【図版未作成】stand・kime・rejectedの3ポーズの例]{alt="3つのポーズの例"}

# 3. ポーズを認識するしくみを作ろう（12分）

ここからは、あなたの3つのポーズをAIに覚えさせます。**モデルは全員が新しく作ります。**

2人1組で、次の役割に分かれて作業してください。途中で交代します。

* **モデル役**：カメラの前でポーズを取る人
* **オペレーター役**：パソコンを操作し、撮影ボタンを押す人

## 3.1 Teachable Machineのポーズプロジェクトを開く

Webブラウザで、次のURLを開いてください。

https://teachablemachine.withgoogle.com/train/pose

![【図版未作成】Teachable Machineのポーズプロジェクトの初期画面]{alt="Teachable Machineのポーズプロジェクトの初期画面"}

「Teachable Machine」は、Googleが提供する機械学習の学習ツールです。プログラムを書かずに、画像・音・ポーズを学習させることができます。

> ⭐️ サインインは不要です。この画面のまま作業を進めてください。

## 3.2 3つのクラスを用意する

画面には「Class 1」「Class 2」という2つの箱があります。この箱を「クラス」と呼びます。AIは「どのクラスに近いか」を判定します。

「Add a class」を1回押して、箱を3つにしてください。そのうえで、クラス名の右の鉛筆アイコンから、名前を次のように変更します。

| もとの名前 | 変更後の名前 |
| --- | --- |
| Class 1 | `stand` |
| Class 2 | `kime` |
| Class 3 | `rejected` |

**半角小文字で、このとおりに入力してください。** 2.2で決めた3つのポーズと同じ名前です。台本もこの名前で書かれているので、1文字でも違うと動きません。

![【図版未作成】クラス名をstand・kime・rejectedに変更した画面]{alt="3つのクラス名を変更した画面"}

## 3.3 ポーズを撮影する

### 3.3.1 撮影の準備

1. オペレーター役が、`stand`クラスの「Webcam」ボタンを押します。
2. カメラの使用を許可します。
3. モデル役がカメラの前に立ち、**上半身**が大きく映るように、ディスプレイの向きとカメラの角度を調整します。
4. カメラに**他の人が映り込んでいないこと**を確認します。

![【図版未作成】カメラの前に立ち、上半身が映っている状態]{alt="カメラの前に立った状態"}

### 3.3.2 3つのポーズを順に撮影する

`stand`・`kime`・`rejected`の順に、同じやり方で撮影します。

1. そのクラスの「Webcam」ボタンを押します。
2. モデル役がそのポーズを取ります。
3. オペレーター役が「Hold to Record（長押しして録画）」ボタンを**押したまま、5秒ほど**待ちます。
4. その間、モデル役はポーズを**少しだけ動かします**（体の向きを少し変える、腕の高さを少し変える）。
5. ボタンを離します。サンプル画像が50枚ほど集まります。

3つとも撮り終えたら、役割を交代せずに次へ進みます。

> ⭐️ まったく同じ姿勢だけを撮ると、少しずれたときに認識できなくなります。**少しだけ動かしながら撮る**のがコツです。

![【図版未作成】3つのクラスにサンプル画像が集まった画面]{alt="3つのクラスにサンプルが集まった画面"}

## 3.4 モデルをトレーニングする

画面中央の「Train Model（モデルをトレーニング）」ボタンを押してください。30秒から1分ほどかかります。

> ⭐️ トレーニング中は、**このタブを他のタブに切り替えないでください**。処理が止まることがあります。

## 3.5 モデルを確認する

画面右側の「Preview」にカメラの映像が表示され、下に3つのバーが出ます。モデル役が3つのポーズを順に取って、**そのポーズのバーだけが100%近くになる**ことを確かめてください。

**うまく判定されないとき**

| 症状 | 対処 |
| --- | --- |
| 別のクラスのバーが上がる | 混ざっている2つを撮り直す。形をもっと離す |
| どのポーズでもバーが揺れる | ポーズをもっと大きな形に変える |
| `stand`と`rejected`が混ざる | `rejected`はうつむく角度を深くする |

撮り直したら、もう一度「Train Model」を押してください。

## 3.6 モデルをクラウドにエクスポートする

できあがったAIを、紙芝居アプリから使えるようにインターネット上へ置きます。

1. 画面右上の「Export Model（モデルをエクスポート）」ボタンを押します。
2. 上部で「**Tensorflow.js**」のタブが選ばれていることを確認します。
3. 「**Upload my model**」ボタンを押します。
4. アップロードが終わるまで30秒ほど待ちます。
5. 「Your sharable link:（共有可能なリンク）」の下にURLが表示されます。

```text
https://teachablemachine.withgoogle.com/models/XXXXXXXXX/
```

![【図版未作成】Export Modelの画面とsharable linkの表示]{alt="Export Modelの画面"}

このURLを**ワークシートに書き写してください**。次の章で台本に入力します。「Copy」ボタンでクリップボードにもコピーできます。

**このタブは閉じないでください。** あとでもう一度コピーすることがあります。

> ⭐️ URLの末尾の`/`（スラッシュ）まで含めて写してください。これがないと読み込めません。

> ⭐️ このURLには、あなたの名前も撮影した映像も含まれません。学習結果だけが置かれます。

# 4. 台本にモデルを組み込もう（12分）

ここからは、紙芝居の台本に、あなたのモデルと絵と言葉を入れます。

## 4.1 ベース作品を開く

配布資料の`tekona-workshop-blocks-4.0.sb3`を、TurboWarp Plus Editorで開いてください。

![【図版未作成】ベース作品を開いた画面]{alt="ベース作品を開いた画面"}

「TurboWarp Plus Editor」は、Scratchによく似た画面でAI紙芝居の台本を編集できるツールです。台本は**ブロックを組み合わせた形**で書かれています。これを「ブロック台本」と呼びます。

> ⭐️ 画面に並んでいるブロックは、Scratchの「動かす」「言う」とは別物です。AI紙芝居専用のブロックです。

## 4.2 自分の席の枠を見つける

この作品には、**席番号ごとの空き枠**が最初から用意されています。あなたの席番号を`NN`（01〜20の2けた）として、次の3つがあなたの枠です。

| もの | 名前 | 中身 |
| --- | --- | --- |
| 場面 | `suitor-NN` | あなたの求婚者が登場する場面。いまは何も再生しない状態 |
| スプライト | `SuitorNN` | あなたの求婚者。`stand`・`kime`・`rejected`の3つの仮のコスチューム（「？」の人物） |
| モデル | `PoseNN` | あなたのポーズ認識モデル。いまは仮のリンク |

枠は、用意済みの求婚者たちのあとに並んでいます。あなたがこれから行うのは、この枠を**自分のものに置き換える**作業です。

<div class="concept-flow">
モデルのURLを入れる → 言葉を書き換える → 枠を有効にする → 反映する
</div>

> ⭐️ 自分の席番号以外の枠は触らないでください。ほかの人の枠です。

## 4.3 モデルのURLを入れる

**ここがこの章の中心です。** 3.6で控えたURLを、台本に入力します。

ステージのブロック台本から、`asset [PoseNN] = JSON [...]`のブロックを探してください。`NN`はあなたの席番号です。`VALUE`の欄には、次のようなJSONが入っています。

```json
{
  "kind": "recognitionModel",
  "delivery": "remote",
  "loading": "lazy",
  "source": {"url": "https://teachablemachine.withgoogle.com/models/REPLACE-WITH-SAMPLE-MODEL/"}
}
```

この`source.url`の値を、**3.6で控えた自分のURLに書き換えます。** ほかの部分は変えません。

![【図版未作成】assetブロックのVALUEでURLを書き換える画面]{alt="モデルのURLを書き換える画面"}

入力するときの注意です。

* 引用符は**半角の`"`**を使います。全角の「”」は使えません。日本語入力をオフにしてください。
* URLの末尾の`/`まで入れます。
* `kind`・`delivery`・`loading`は変えません。

> ⭐️ `loading: lazy`は「この場面の直前に読み込む」という指定です。全員分のモデルを最初にまとめて読み込むと時間がかかるため、こうなっています。

## 4.4 言葉を書き換える

場面`suitor-NN`の中に、セリフのブロックが並んでいます。〔　〕で囲まれた部分が、書き換える場所です。

2.1のワークシートに書いた、身分・外見・名乗りのセリフを入れてください。手児奈の断りの言葉は、書き換えません。

## 4.5 枠を有効にする

あなたの枠は、いま`if`のブロックの中に入っていて、条件が`false`になっています。これは「まだ再生しない」という意味です。

この条件を`true`に変えてください。これであなたの場面が物語の中で再生されるようになります。

![【図版未作成】条件をtrueに変える画面]{alt="枠を有効にする画面"}

## 4.6 反映して保存する

ここまでの編集を、作品に反映します。

1. 文書の書類アイコンから内容を確認します。
2. 「**表示されている形式に変換して検証・保存**」を押します。
3. エディタのメニューからSB3も保存します。

ブロックを編集しただけでは、まだ作品に入っていません。この操作で、編集した内容が検証されて台本に反映されます。

エラーが出た場合は、次の表で原因を探してください。

| 表示・症状 | 確認する場所 |
| --- | --- |
| `must be string`、`/assets/...`のSchemaエラー | 4.3のJSON。引用符が全角になっていないか、`source`の内側に`url`があるか |
| `Unknown reference`、`Unknown actor` | コスチューム名。`stand`・`kime`・`rejected`のままか（4.7） |
| 読み込みは終わるが次へ進まない | クラス名。Teachable Machineの3つが`stand`・`kime`・`rejected`か（3.2） |
| 自分の場面が再生されない | 4.5の条件が`true`になっているか |

エラーの表示には、問題のあるブロックの名前が日本語で出ます。クリックするとその場所に移動できます。わからないときはスタッフを呼んでください。

> ⭐️ 台本は、絵とセリフを並べただけのものではなく、**プログラム**です。名前が1文字違うだけで動かなくなるのは、プログラムだからです。逆に言えば、名前をそろえれば必ず動きます。

## 4.7 絵を差し替える（時間が余ったら）

スプライト`SuitorNN`を選び、「コスチューム」タブを開くと、`stand`・`kime`・`rejected`の3つが「？」の人物になっています。これがあなたの求婚者の仮の姿です。

**時間内は、この仮の絵のままでかまいません。** 40分では絵を描く時間が取れないため、あなたの求婚者の姿は、ワークシートに書いた外見と、あなた自身のポーズで表します。

5章まで終わって時間が余った人は、配布資料の`suitors`フォルダから、自分の考えた求婚者に近い3枚（`…Stand`・`…Kime`・`…Rejected`）を選び、コスチュームを差し替えてください。差し替えたら、4.6の「表示されている形式に変換して検証・保存」をもう一度押します。

**コスチュームの名前は変えないでください。** 台本がこの名前で参照しています。

# 6. まとめ（3分）

## 6.1 みんなの求婚者を並べてプレイしよう

スタッフが、クラス全員の求婚者を1つの一覧にまとめます。
求婚者が次々に現れて、手児奈に断られていく紙芝居になります。

手児奈は、**全員を断ります**。誰か1人を選ぶことができないまま、物語は結びに向かいます。

## 6.2 今日あなたが達成したこと

40分で、次のことを行いました。

* 地域に伝わる伝説を読み、そこに登場する人物を自分で考えた
* 自分の体の動きを、AIに学習させた（機械学習）
* 学習したAIをインターネット上に公開し、そのURLで別のアプリから呼び出した
* プログラム（台本）の決まった場所に、決まった形でデータを書き込み、動作させた
* エラーの表示を読み、原因を探して直した

これは、**AIを「使う」だけでなく、AIを「組み込む」**作業です。

## 6.3 考えてみよう

持ち帰ってほしい問いが3つあります。答えは1つではありません。

**1. 手児奈はなぜ、誰も選べなかったのでしょうか。**

伝説では「1人を選べば他の人を悲しませてしまうから」と語られます。
では、求婚した人たちは、手児奈の何を見ていたのでしょうか。
手児奈自身が望んだことは、物語の中で語られているでしょうか。

**2. AIが「断る」とは、どういうことでしょうか。**

今日作った紙芝居では、AIがポーズを認識し、台本に書かれた断りのセリフが表示されました。
手児奈が「考えて断った」のではなく、**台本にそう書いてあったから断った**のです。
では、人の申し出に答えるAIが実際にあるとしたら、その答えは誰が決めているのでしょうか。

**3. 生成AIで人物の絵を作るとき、何に気をつけるべきでしょうか。**

この作品に入っている求婚者の絵は、生成AIで作ったものです。
『万葉集』には求婚者の名前も姿も書かれていません。あなたが今日考えた求婚者も、
わたしたちが想像で埋めた部分です。その想像は、誰かを傷つけていないでしょうか。

## 6.4 発展課題

時間があるときに、次のことを試せます。

* **自分だけの求婚者の絵を作る** — 棒人間でポーズの下書きを描き、生成AI（M365 Copilotなど）に
  立ち絵をそのポーズに変えてもらいます。手順は、2026年8月1日版の教材
  「2. AIに乙姫様を描いてもらおう」と同じです。
* **断り方を増やす** — 用意済みの求婚者の一覧に列を追加し、`if`のブロックで手児奈の返事を枝分かれさせます。
* **求婚者を増やす** — その一覧に行を追加すれば、同じ展開がその人数分繰り返されます。
* **現代版を作る** — 舞台を現代の市川に移し、現代の人物として求婚者を考えます。

ブロック台本の書き方は、[DSL 4.0 台本作成ガイド](../../block-author-guides/dsl-4.0-block-author-guide.md)に
詳しく書かれています。
